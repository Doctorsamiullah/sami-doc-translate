# 13. TESTING-QA.md
## Quality Assurance, Translation Evaluation & Test Plans

---

### 1. Test Architecture Matrix

| Test Level | Windows Desktop (`windows-app/`) | Android Native (`android-app/`) |
| :--- | :--- | :--- |
| **Unit Testing** | `pytest tests/unit` | `JUnit 5 + MockK` |
| **UI Testing** | `pytest-qt` (PySide6 UI) | `Compose UI Test / Espresso` |
| **End-to-End** | Sample DOCX/PDF batch runs | Robot pattern end-to-end tests |
| **Memory Stress Test**| 500-page synthetic PDF streaming | 100-page background WorkManager run |

---

### 2. Quality Evaluation Metrics (BLEU & chrF++)
DocTranslate evaluates translation quality against standardized Hindi parallel corpora (IIT Bombay English-Hindi Corpus / FLORES-200):
- **Target BLEU Score**: > 32.0 (English → Hindi) and > 35.0 (Hindi → English).
- **Target chrF++**: > 55.0 for Hindi (critical for capturing morphological affixes and conjuncts).
- **Format Integrity Score**: 100% of tables, images, and run-level styles must persist in output documents.

---

### 3. Unlimited-Page Memory Stress Test
DocTranslate runs automated stress benchmarks on every release candidate:
1. Generate synthetic 250-page, 500-page, and 1,000-page documents filled with paragraphs, tables, and headers.
2. Stream through translation pipeline with OS memory profilers active (`memory_profiler` on Python, Android Profiler on Android).
3. **Pass Criteria**:
   - Python resident set size (RSS) must never exceed 600 MB.
   - Android process RAM must never exceed 250 MB.
   - Garbage collector invocation must cleanly reclaim memory between pages.
