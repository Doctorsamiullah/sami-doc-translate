# 30. CONTRIBUTING.md
## Contributor Guidelines, Pull Requests & Code Review Checklist

---

### 1. Code of Conduct & Contribution Philosophy
We welcome contributions to DocTranslate! Whether you are implementing a new document format parser, optimizing Devanagari line-height calculations, or improving offline translation quality, please adhere to our quality gates.

---

### 2. Git Workflow & Branching
1. Fork the repository and create a descriptive branch:
   - `feat/docx-table-alignment`
   - `fix/matra-clipping-pdf`
   - `docs/update-architecture`
2. Follow **Conventional Commits**:
   - `feat(windows): add streaming generator for pptx text frames`
   - `fix(android): resolve SAF content resolver leak on Android 14`
   - `test(core): add 500-page OOM stress test`

---

### 3. Pre-Commit Checklist
Before submitting a Pull Request:
- [ ] **Windows App**:
  - `black src/ tests/` passes.
  - `flake8 src/ tests/` reports 0 errors.
  - `pytest tests/` passes 100%.
- [ ] **Android App**:
  - `.\gradlew.bat testDebugUnitTest` passes.
  - `.\gradlew.bat ktlintCheck` passes.
- [ ] **Zero-OOM Guarantee**: Does your file parser load the entire document into RAM at once? If yes, refactor it into a streaming generator.
- [ ] **Font Handling**: Does Hindi output use `Noto Sans Devanagari` or `Mangal`?
- [ ] **Documentation**: Have you updated relevant `.md` files in `docs/`?

---

### 4. Submitting a Pull Request
Open a PR against the `main` branch. Provide a concise description of changes, screenshots/video of UI changes (for PySide6 or Compose), and benchmark logs for performance improvements.
