# 23. ERROR-HANDLING.md
## Fault Taxonomy, Error Handling & Recovery Strategies

---

### 1. Error Taxonomy & User-Facing Actions

| Error Code | Error Category | Trigger Scenario | Automated System Action | User Guidance |
| :--- | :--- | :--- | :--- | :--- |
| `ERR_FILE_CORRUPTED` | Ingestion | Malformed XML in DOCX or truncated PDF EOF | Abort file job; log stack trace; isolate file | "File appears corrupted. Please re-save or repair in source app." |
| `ERR_PASSWORD_PROTECTED`| Ingestion | Encrypted or password-locked PDF | Detect encryption flag before processing | "This document is password protected. Please unlock it before translating." |
| `ERR_MODEL_MISSING` | Engine | Offline weights not found on disk | Prompt download manager dialog | "Offline Hindi model pack is missing (~30MB). Tap 'Download' to install." |
| `ERR_OOM_PREVENTED` | Streaming | Memory threshold (>500MB) approaching | Flush page cache to disk; run garbage collection | "Processing large document in safe low-memory streaming mode..." |
| `ERR_IO_WRITE_LOCKED` | Export | Target output file open in Microsoft Word | Retry with exponential backoff (3 attempts) | "Target file is currently open in another app. Please close Word and retry." |

---

### 2. Checkpoint Recovery Architecture

When translating large 100+ page documents:
1. Every completed page is flushed to the output disk stream.
2. The page index is saved to SQLite/Room DB (`job_checkpoints`).
3. If an unhandled exception or power loss occurs:
   - On application restart, DocTranslate detects unfinalized jobs in `job_checkpoints`.
   - The user is prompted: *"Resume translation of Document.pdf from page 42?"*
   - Execution resumes without retranslating previous pages.
