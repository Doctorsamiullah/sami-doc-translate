# 10. AUTH-SECURITY.md
## Authentication, Cryptography & Offline Security Model

---

### 1. Zero-Trust Offline Security Philosophy
DocTranslate operates on an offline-first, zero-trust security paradigm:
1. **Zero External Data Exfiltration**:
   - The application does NOT send document contents, sentence hashes, or user telemetry to any remote server.
   - Translation models execute strictly on the local CPU/GPU/NPU.
2. **Local Credential Storage**:
   - If the user enables an optional online API (e.g., custom OpenAI, Anthropic, or Ollama endpoint), API keys are NEVER stored in plaintext `.env` or config files.
   - **Windows**: Keys are encrypted using the Windows Data Protection API (DPAPI) or stored via Windows Credential Manager (`keyring` library).
   - **Android**: Keys are stored using Android Jetpack Security (`EncryptedSharedPreferences` backed by the hardware Android Keystore).

---

### 2. File Deserialization & Path Traversal Mitigations
- **Zip-Slip Protection**: When reading `.docx`, `.pptx`, or `.xlsx` files (which are zipped XML archives), all file paths extracted from the zip are canonicalized and verified to prevent writing outside the designated scratch directory.
- **Buffer Overflow & Memory Bomb Defenses**: Decompression ratio limits (maximum 100:1) to prevent Zip bombs. Maximum single-file size thresholds (configurable, default 2 GB).
- **Sanitized Filenames**: When exporting translated documents, special control characters and directory separators (`/`, `\`, `..`) are stripped from proposed export names.
